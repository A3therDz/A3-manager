## 二、四种元数据格式

你的图**不是同一种格式**,这是最容易踩的坑。

### F1 原生 API 节点图
```
tEXt["prompt"] = { "2340": {"class_type":"KSampler","inputs":{...}}, ... }
```
参数**不是字面量**,而是链接:`"steps": ["474", 0]` 表示"取节点 474 的第 0 号输出"。
必须做图遍历求值。

### F2 嵌套图
```
tEXt["prompt"] = { "prompt": {节点图}, "workflow": {...} }
```
外层包了一层。出现在 `output/anima/`。

### F3 A1111 文本格式(你库里最多的一种,4654 张)
```
tEXt["parameters"] = "正提示词\nNegative prompt: 负提示词\nSteps: 30, Sampler: ..., CFG scale: ..., Seed: ..., Size: ..., Hashes: {...}, Version: ComfyUI"
```
**关键陷阱**:负提示词在参数行的**之后**,不在前面。任何"按行切分"的朴素解析都会吞掉它。
LoRA 藏在提示词的 `<lora:名字:权重>` 标签里(你的图最多一张挂 10 个 LoRA)。
`Size:` 是**请求尺寸**,不等于实际输出尺寸(你的很多图经过放大,例如请求 1248x1824 → 实际 1560x2280)。

### F4 无文本块
`dis/` 的 701 张完全没有文本块。不是解析失败,是元数据被上游工具剥掉了。

### F5 UI 工作流格式(仅 `workflow` 块)
参数在 `nodes[].widgets_values` **数组位置**里,没有键名。位置随节点版本变化,
只能按形态特征识别 + 合理性校验压制误判。

## 三、必须记住的三个数据缺陷

### 1. `NaN` 会写进元数据(致命)
某些自定义节点(如 `LoadImage`)会把 JavaScript 的 `NaN` 直接序列化进去:
```json
{"inputs": {...}, "is_changed": NaN}
```
**这不是合法 JSON,`JSON.parse` 会直接抛错。** 全库有 **2463 张**受影响。
解析前必须消毒(本项目用 `parseJsonLenient`)。

### 2. rgthree 参数控制面板不写值(无解)
你的复杂工作流大量使用 rgthree 的 `ParameterControlPanel` + `ParameterBreak` + `KSampler Config`:
```
KSampler.sampler_name -> ["477",3]        KSampler Config (rgthree)
  -> ["3847",2]                           ParameterBreak
    -> ["3846",0]                         ParameterControlPanel
      -> inputs = {"pcp_ui": ""}          ← 值是空字符串!
```
**采样器名/调度器根本没被写进元数据。** 影响 2104 张。
这是数据缺失,不是解析 bug。所以详情面板必须容忍这两个字段为空。

### 3. 转发节点会把参数解析到错误槽位
同样的 rgthree 链路会让朴素的"取第一个可解析值"拿到 **步数**("30")当作采样器名。
必须加形态闸门(`plausibleSampler`:拒绝纯数字、长度上限、必须含字母)。

## 五、性能设计要点

- **只读需要的块就停**。`workflow` 块可达 1.5MB 且可能排在参数块**之前**,
  所以策略是:记住它但不立刻采用,只有当整份扫描结束仍未拿到 `prompt`/`parameters`
  时才回头用它。
- 只读 `prompt` / `parameters` 的路径:全库 8061 张 **4 秒**。
- 保留 `rawPromptJson` 会让耗时翻 10 倍以上(最大单块 1.6MB),所以**索引路径不保留原始 JSON**,
  只在详情接口按需读取。

## 六、给前端(Kimi K3)的硬性要求

1. 详情面板**必须容忍** `sampler.samplerName` / `scheduler` 为 `null`,显示"未记录"而不是空白或报错。
2. 参数可能有**多个采样器**(`allSamplers`,145 张多采样器工作流),默认展示 `sampler`(最终那一段),可折叠看全部。
3. A1111 图的 `modelName` 是显示名(如 `anima_baseV10`),节点图的是文件名(如 `*.safetensors`),
   **不能假设格式统一**。
4. 尺寸一律用 `dimensions`(IHDR 实测值),不要用 A1111 的 `Size` 字段(那是请求尺寸)。
5. `customNodeHints` 里可能带"请求尺寸 X,实际输出 Y(经过放大处理)"这类提示,应当展示。
